# ADR 0028: Review case comments

- Status: Accepted
- Date: 2026-11-06
- Follow-up: A comment is an immutable Reconciliation entry. It is not a dispute, a reopen, or a `ReviewCaseAuditAction`. Phase 8 stays planned. There is no comment screen in this increment.

## Context

ADR 0009 closes a review case with resolve or dismiss and does not reopen it. ADR 0025 records `Opened`, `Resolved`, and `Dismissed` in `ReviewCaseAuditEntry`. Those rows describe the decision. They are not a place for later notes. An operator still needs to append plain text to an open or already closed case without changing the decision, `ClosedAt`, `rowversion`, balances, or the existing audit rows.

## Decision

`ReviewCaseComment` belongs to Reconciliation. A row stores `Id`, `OrganizationId`, `ReviewCaseId`, `Text`, `ActorId`, `RecordedAt`, and `IdempotencyKey`. There is no second audit table and no `Commented` action. The comment can be appended while the case is `Open`, `Resolved`, or `Dismissed`. The save inserts only the comment. It does not attach the case, so the case `rowversion` stays unchanged.

`POST /api/review-cases/{id}/comments` accepts only `text`. The value is required plain text. Normalization is `string.Trim()`. After that, the length must be 1 to 500 UTF-16 code units. Whitespace-only text is rejected. U+FEFF is preserved because `Trim` does not treat it as whitespace. HTML is stored as text and is not interpreted. The server supplies the organization, the actor, and the time. The client cannot send attribution.

`Idempotency-Key` is required. It must be exactly one non-empty UUID in `D` format, with no surrounding `Char.IsWhiteSpace`, because `Guid.TryParseExact` trims those characters. A missing header returns `reconciliation.review_case_comment.idempotency_key_required`. A present but invalid header returns `reconciliation.review_case_comment.idempotency_key_invalid`. The key is scoped to the organization and this operation by `UX_ReviewCaseComments_OrganizationId_IdempotencyKey`.

The handler requires a valid actor before it reads the key, including on replay. An existing key is compared with the route case id and the normalized text using `StringComparison.Ordinal`. A match returns HTTP 200 and the original id, actor, and `RecordedAt`. A different case or text returns HTTP 409 `reconciliation.review_case_comment.idempotency_payload_conflict`, including when the requested case is unknown. Only a new key checks that the case exists in the organization. Unknown and foreign cases then share HTTP 404 `reconciliation.review_case.not_found`. The same normalized text with a new key may append another comment. A new comment returns HTTP 201 with no `Location` header. There is no single-comment route.

A unique violation is not success by itself. Recovery recognizes SQL Server error 2601 or 2627 only when the message names `UX_ReviewCaseComments_OrganizationId_IdempotencyKey`. The winner is read on a new context. A matching payload returns HTTP 200. A different payload returns the payload conflict. A missing winner returns HTTP 409 `reconciliation.review_case_comment.concurrency_conflict`. The failed context is not saved again. A primary key, foreign key, or another index is not replay.

`GET /api/review-cases/{id}/comments` returns `items`, `page`, `pageSize`, and `totalCount`. `totalCount` is a 64-bit count from `LongCount`. Each item has the same shape as the POST response. Page defaults to 1 and page size defaults to 50, with a maximum of 100. The offset is calculated in 64-bit arithmetic and must fit in `Int32`. Ordering is `RecordedAt` ascending, then `Id` ascending. An existing case with no comments returns an empty page. The existence check, the count, and the page are separate statements and are not one snapshot.

The composite foreign key is `(OrganizationId, ReviewCaseId)` to `AK_ReviewCases_OrganizationId_Id`, with `DeleteBehavior.Restrict`. Comment ids are generated by the domain (`ValueGeneratedNever`). SQL checks reject an empty idempotency key, a blank or over-long actor, and text whose `DATALENGTH` is outside 2 to 1000 after `LTRIM` and `RTRIM`. Those SQL functions remove only U+0020. Domain `Trim` removes every .NET whitespace character. `TR_ReviewCaseComments_RejectMutation` rejects `UPDATE` and `DELETE` with error 50003. `UseSqlOutputClause(false)` is required because of that trigger.

Both routes stay under `TenantMember`. The organization comes only from `ICurrentOrganizationContext`. GET requires `audit.read`. POST is `review-cases.comment`, `FinancialWriteOperation.CommentReviewCase` value 11, and is granted only to `Operator`. The permission is a known write classification, so `DevelopmentJwt` can post. It is not in `ProductionFinancialWriteActivation` and is not advertised as a cookie write. `ProductionCookie` may GET when the read flag is active and `audit.read` is present. Cookie POST stays outside the allowlist when both flags are enabled. `FinancialCommitGuard` and the deployed flags are unchanged. A missing or invalid actor returns the existing `reconciliation.actor.required`.

## Consequences

- Closed cases can receive comments and stay closed.
- Comment history is append-only in the application and in SQL Server.
- Down drops the trigger and the table, so it deletes stored comments. It is not a production rollback.
- There is no backfill and no edit, delete, reply, or attachment API.
- Phase 8 stays planned.

## Alternatives considered

### Add `Commented` to `ReviewCaseAuditAction`

Rejected. The audit row would copy the same text and would change the meaning of the decision history. The history panel would have to understand a fourth action.

### Store the key in a separate attempt table

Rejected. The comment row is the durable result. A second table would copy the same payload without adding a recovery path.
